Evidence-only; no device used.

1. WHAT EACH STOCK TOUCH DRIVER ASKS FOR
===============================================================================
icnl9916_tddi_mmi.ko  (Chipone) — REA/Ghidra: cts_request_firmware @ 0x108a14
  string refs: 0x11d99a, 0x12325d, 0x12452c
  hw id 0x990160 -> "/vendor/firmware/ICNL9916.bin"   (name passed to request: "ICNL9916.bin")
  hw id 0x991110 -> "/vendor/firmware/ICNL9911.bin"   (name: "ICNL9911.bin")
  other ids      -> return 0 (no update)
  Then cts_request_newer_firmware_from_fs(): updates the IC only if the file carries a
  newer firmware version. If the path is not present/readable it returns 0.
  INFERRED: this is an UPDATE path, not a probe requirement -> a missing file does not by
  itself fail the probe (the IC keeps its factory-flashed firmware).

5. INTERPRETATION
===============================================================================
- The **Ilitek (ILI9883A)** SKU was complete before this change: module + exact firmware.
- The **Chipone (ICNL9916)** SKU was missing ICNL9916.bin / ICNL9911.bin; both are now
  shipped in the recovery ramdisk. INFERRED non-fatal for probing even when absent
  (update-only path), so this closes a firmware-update gap rather than a proven
  cause of the dead touchscreen.
- Only TWO panel SKUs exist for tonga: the kernel LCM drivers are
  mipi_mot_vid_tm_icnl9916_652_hdp and mipi_mot_vid_tm_ili9883a_652_hdp, and
  vendor/etc/motorola/12m/ carries configs for exactly those two families
  (chipone-tianma_icnl9916..., chipone-txd_icnl9911c..., TM655_driver_Command_ilitek_tm.ini).
  There is no third (novatek) SKU to support. INFERRED from those two sources.
- The 12m .ini files are factory-test configs, not probe inputs: neither module
  references /vendor/etc/motorola (ili9882_mmi.ko only references mp*.ini /
  /sdcard/ILITEK_FW_* test paths; icnl9916_tddi_mmi.ko only /vendor/firmware/*.bin).
- The SKU itself cannot be determined from the firmware dump: stock ships both variants
  and both panel names are compiled into the kernel. Confirm on-device:
      dmesg | grep -E 'CTS-I2CDrv|ILITEK'      (prints active_panel_name / the bail-out reason)
      cat /proc/cmdline                        (contains the selected mipi_mot_vid_* token)
  Both are now also captured automatically into /tmp/touch_dbg.log (touch-diag service).
